Set up a Reolink camera with Magi Experimental · CX820

Connect and power the camera on the Pi's local network. Find it below or enter its private IPv4 address above. Magi uses the camera's local setup service on port 9000, even when HTTP and RTSP are disabled. No Windows software or cloud login is needed on supported firmware.

The suggested /24 comes from the Pi connection or saved camera address; edit it if needed. Search checks up to 254 local addresses for a compatible Reolink setup service; it does not try passwords. Discovery is limited to port 9000. Cameras on other VLANs or custom setup ports may not appear.

For an existing camera, leave initialization unchecked and use its username and password above; a blank password field reuses the saved login for the same camera. For a new camera, check initialization, use admin, leave the existing password blank, and choose and confirm a new password BEFORE clicking Inspect. Inspection does not create the password; Apply creates it. New passwords must be 8–31 printable ASCII characters without spaces.

Motion detection

Event types & footage retention

Automatic types are candidates, not confirmed identifications. Manual saves always keep footage.

Keep footage for:

Excluded motion/flash/meteor types keep a small event record without footage. Aircraft/satellite rules apply after an unambiguous reference result; they need reference checks, calibration and initial motion recording. Footage for excluded matches is discarded, while the event and reference report stay. Unavailable, ambiguous or no-match results keep their initial footage. Manual, protected, annotated or reviewed events are not discarded by these match rules. A mixed event is kept if it also contains a retained meteor or lightning candidate. Changes apply to new captures; existing events are unchanged.

Exposure changes can mimic lightning; aircraft, insects and other objects can mimic meteors. Broad slow illumination changes remain suppressed. Detection uses the native substream and can miss very brief, dim or discontinuous events. These controls do not upload video or alter the original camera stream.

Lower thresholds are more sensitive and can create more false events. Tiny, faint or very brief objects may be missed. This prototype does not classify objects.

RECORDINGS & DISK SPACE
Storage.
Active cameras and removed-camera archives share physical disk space.
 
These actions include removed-camera archives. Preview and confirm before permanently deleting footage and metadata. Protected and in-use events are skipped. Capture buffers are not cleared while a camera is active.
How cleanup works
Each active camera clears its own oldest unprotected events when its cap or free-space floor is reached. Trash goes first. Age retention also applies. Protected events and recordings in use are skipped; capture can pause if space cannot be reclaimed.
Removed-camera archives are never automatically cleaned, even when trashed. Use Delete archived camera to permanently remove an empty/unprotected archive after confirmation. Protected or unreadable events block removal. Counts include buffers and sidecars; hardlinks within each camera are counted once. These are file sizes, not exact filesystem allocation. Disk free space also reflects the OS, logs and other files.
Logs
Install/update logs in /var/log/magi are managed daily: completed logs expire after 30 days, with at most 20 files and 50 MiB retained. Logs still being written are skipped. Update logs roll at 5 MiB, keeping three backups per run. Older uncoordinated logs are left untouched for 24 hours.
Runtime service logs use the system journal and its existing rotation policy. This release does not change system-wide journal limits.
